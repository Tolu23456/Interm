1. STARTUP + BOOT SYSTEM
============================================================

SYSTEM: startup_boot_system

RESPONSIBILITY:
Controls how INTERM initializes from zero state to fully operational editor.

BOOT ORDER:

1. Terminal Backend Initialization
2. Memory Allocator Setup
3. Event System Startup
4. Async Runtime Boot
5. Core API Layer Initialization
6. VFS Initialization
7. Buffer System Startup
8. Renderer Initialization
9. Input System Activation
10. Syntax Engine Load
11. State Machine Activation
12. Git System Initialization
13. LSP Manager Startup
14. Plugin System Load (sandboxed)
15. AI Engine Initialization (optional)
16. UI Layout Bootstrap

RULES:
- boot must be deterministic
- each stage must validate success before proceeding
- failures must fallback safely (safe mode)
- partial boot allowed (degraded mode)

FEATURES:
- lazy subsystem loading
- fast startup path (<10ms target cold start goal)
- crash-safe recovery boot mode

============================================================

SYSTEM: lsp_integration_layer

RESPONSIBILITY:
Manages all language server communication.

CORE FEATURES:

- multi-LSP server support per workspace
- request multiplexing
- response batching
- diagnostics merging system
- semantic + syntax coordination

LIFECYCLE:

1. detect language
2. start appropriate LSP server
3. establish JSON-RPC channel
4. register buffer context
5. stream diagnostics/completions

ADVANCED FEATURES:
- multi-server conflict resolution
- fallback LSP provider
- incremental document sync
